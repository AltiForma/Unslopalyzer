# UN001: Extract complex condition into a named variable

Flags `if`, `while`, `do-while` and ternary conditions that chain too many `&&`/`||` operands or span multiple lines.

| Property             | Value                                            |
|----------------------|--------------------------------------------------|
| Rule ID              | UN001                                            |
| Title                | Extract complex condition into a named variable  |
| Category             | Readability                                      |
| Default severity     | Warning                                          |
| Enabled by default   | Yes                                              |
| Code fix available   | No                                               |

## Rationale

Coding agents tend to pile guard clauses into a single condition. The resulting branch is correct but says nothing about *why* it is taken: the reader has to evaluate every operand to work out what the branch means.

Assigning the condition to a local whose name states its meaning documents the intent at the point of use, and makes the branch read like a sentence.

## How operands are counted

An operand is each side of a `&&` or `||`. Chains are flattened, and parentheses around a nested `&&`/`||` are looked through, so `a || (b && c)` has three operands.

Everything else counts as **one** operand, however complex it is:

- negation: `!x`
- comparisons: `a > b`, `x == null`
- `is` patterns, including `is not null` and the pattern combinators `and`, `or` and `not`: `name is null or ""` is one operand
- method calls and `await`
- the operators `?:`, `??`, and the non-short-circuit `&`, `|` and `^`
- anything inside a lambda or a method argument: `orders.Any(o => a && b && c)` is one operand

## When it reports

A condition is reported when **either** of these is true:

1. **Too many operands:** it has more than `max_operands` operands (default 2, so three or more are reported). The message reads *"Condition has 3 operands, more than the maximum of 2"*.
2. **Wrapped across lines:** it has at least two operands **and** the condition itself, meaning the text between `if (` and `)`, spans more than one line. The message reads *"Condition has 2 operands and spans multiple lines"*.

A condition with a single operand is never reported by UN001. A single operand that wraps across lines is reported by [UN004](UN004.md) instead.

The second trigger depends on how your code is formatted. With CSharpier, a two-operand condition with long names wraps onto several lines and is reported, while a short one fits on one line and is not. If a wrapped two-operand condition is reported, that is the reason. Extract it into a named variable.

### Worked examples (default `max_operands = 2`)

| Condition | Operands | On one line? | Reported? |
|-----------|----------|--------------|-----------|
| `!ModelState.IsValid \|\| !validation.IsValid` | 2 | Yes | No |
| The same condition wrapped so each operand is on its own line | 2 | No | Yes, wrapped across lines |
| `user is not null && user.IsActive` | 2 | Yes | No |
| `user is not null && user.IsActive && !user.IsLocked` | 3 | Yes | Yes, too many operands |
| `isAdmin \|\| (isOwner && isPublished)` | 3 | Yes | Yes, too many operands |
| `name is null or "" or "unknown"` | 1 | Yes | No |
| `a & b & c` | 1 | Yes | No |
| `IsWithinRange(` *(arguments on separate lines)* `)` | 1 | No | No (UN004 reports it) |

## Examples

### Non-compliant

```csharp
if (
    user is null
    || !await signIn.CanSignInAsync(user)
    || await users.IsLockedOutAsync(user)
    || !User.HasScope(Scopes.OpenId)
)
    return Challenge(OpenIddictValidationAspNetCoreDefaults.AuthenticationScheme);
```

```csharp
if (
    privateKey is null
    || certificate.NotBefore.ToUniversalTime() > now.UtcDateTime
    || certificate.NotAfter.ToUniversalTime() <= now.UtcDateTime
)
    throw new CryptographicException("The certificate is not usable for key encryption.");
```

### Compliant

```csharp
var cannotSignIn =
    user is null
    || !await signIn.CanSignInAsync(user)
    || await users.IsLockedOutAsync(user)
    || !User.HasScope(Scopes.OpenId);

if (cannotSignIn)
    return Challenge(OpenIddictValidationAspNetCoreDefaults.AuthenticationScheme);
```

```csharp
var certificateIsUnusable =
    privateKey is null
    || certificate.NotBefore.ToUniversalTime() > now.UtcDateTime
    || certificate.NotAfter.ToUniversalTime() <= now.UtcDateTime;

if (certificateIsUnusable)
    throw new CryptographicException("The certificate is not usable for key encryption.");
```

## Known limitations

- Only `if`, `else if`, `while`, `do-while` and ternary conditions are checked. Boolean expressions in `return` statements, assignments and arguments are not, because the method or variable name already describes them.
- Operand counting stops at lambdas and invocations: `orders.Any(o => a && b && c)` counts as one operand.
- A single operand that wraps across lines, such as a long method call, does not trigger UN001. [UN004](UN004.md) covers that case.
- There is no code fix by design. The value of the rule is a name that explains the intent, which a tool cannot choose.

## Configuration

```ini
[*.cs]
dotnet_diagnostic.UN001.severity = warning
dotnet_diagnostic.UN001.max_operands = 2
```

`max_operands` is the largest number of operands a condition may have. A condition with more is reported, so with `max_operands = 2` two operands pass and three are reported. It does not affect the second trigger: a condition with two or more operands that wraps across lines is reported whatever this is set to. Values that are not positive integers fall back to the default of 2.
