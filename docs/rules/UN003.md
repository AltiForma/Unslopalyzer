# UN003: Try statement should wrap an entire method body

Flags `try` statements, with `catch`, `finally` or both, that sit in the middle of a block instead of being the whole body of a method.

| Property             | Value                                            |
|----------------------|--------------------------------------------------|
| Rule ID              | UN003                                            |
| Title                | Try statement should wrap an entire method body  |
| Category             | Design                                           |
| Default severity     | Warning                                          |
| Enabled by default   | Yes                                              |
| Code fix available   | No                                               |

## Rationale

Coding agents tend to drop a `try` around whichever call might throw, right where it happens to be in a long method. The error handling for that one operation then gets tangled with everything around it:

- variables declared before the `try` only so the `catch` can assign a fallback
- early returns from inside a `catch` that skip the rest of the method
- logic after the `try` that silently depends on which branch ran

A `try` should guard exactly one operation, and a method is the natural boundary for one operation. Extracting the guarded code into its own method gives the operation a name. It also keeps the error handling next to the only code it applies to, and turns the caller back into a straight sequence of steps.

A `try` statement is allowed when it is the body of a method, constructor, accessor, local function or lambda:

- it must be the first statement in that body
- it may be followed by at most one `return` statement
- local function declarations after it are ignored

Every other `try` is reported, including one inside a loop, an `if`, a `using` block, or another `try` or `catch`.

## Examples

### Non-compliant

Parsing guarded in the middle of an import:

```csharp
public async Task<int> ImportAsync(Stream upload, CancellationToken cancellationToken)
{
    using var reader = new StreamReader(upload);
    var text = await reader.ReadToEndAsync(cancellationToken);

    IReadOnlyList<Product> products;
    try
    {
        products = CsvParser.Parse<Product>(text);
    }
    catch (CsvFormatException exception)
    {
        logger.LogWarning(exception, "Rejected product upload");
        return 0;
    }

    catalog.AddRange(products);
    await catalog.SaveChangesAsync(cancellationToken);
    return products.Count;
}
```

A retry loop with the attempt inlined:

```csharp
public async Task<bool> CaptureAsync(Payment payment, CancellationToken cancellationToken)
{
    for (var attempt = 1; attempt <= 3; attempt++)
    {
        try
        {
            await gateway.CaptureAsync(payment.Id, cancellationToken);
            return true;
        }
        catch (GatewayTimeoutException)
        {
            await Task.Delay(TimeSpan.FromSeconds(attempt), cancellationToken);
        }
    }

    return false;
}
```

Cleanup guarded part-way through a method:

```csharp
public async Task<int> StoreAsync(string key, byte[] image, CancellationToken cancellationToken)
{
    var thumbnail = resizer.Shrink(image, maxWidth: 256);

    await gate.WaitAsync(cancellationToken);
    try
    {
        cache[key] = thumbnail;
    }
    finally
    {
        gate.Release();
    }

    return thumbnail.Length;
}
```

### Compliant

```csharp
public async Task<int> ImportAsync(Stream upload, CancellationToken cancellationToken)
{
    using var reader = new StreamReader(upload);
    var text = await reader.ReadToEndAsync(cancellationToken);

    var products = TryParseProducts(text);
    if (products is null)
        return 0;

    catalog.AddRange(products);
    await catalog.SaveChangesAsync(cancellationToken);
    return products.Count;
}

private IReadOnlyList<Product>? TryParseProducts(string text)
{
    try
    {
        return CsvParser.Parse<Product>(text);
    }
    catch (CsvFormatException exception)
    {
        logger.LogWarning(exception, "Rejected product upload");
        return null;
    }
}
```

```csharp
public async Task<bool> CaptureAsync(Payment payment, CancellationToken cancellationToken)
{
    for (var attempt = 1; attempt <= 3; attempt++)
    {
        var captured = await TryCaptureOnceAsync(payment, cancellationToken);
        if (captured)
            return true;

        await Task.Delay(TimeSpan.FromSeconds(attempt), cancellationToken);
    }

    return false;
}

private async Task<bool> TryCaptureOnceAsync(Payment payment, CancellationToken cancellationToken)
{
    try
    {
        await gateway.CaptureAsync(payment.Id, cancellationToken);
        return true;
    }
    catch (GatewayTimeoutException)
    {
        return false;
    }
}
```

```csharp
public async Task<int> StoreAsync(string key, byte[] image, CancellationToken cancellationToken)
{
    var thumbnail = resizer.Shrink(image, maxWidth: 256);

    await gate.WaitAsync(cancellationToken);
    StoreLocked(key, thumbnail);
    return thumbnail.Length;
}

private void StoreLocked(string key, byte[] thumbnail)
{
    try
    {
        cache[key] = thumbnail;
    }
    finally
    {
        gate.Release();
    }
}
```

A single trailing `return` is allowed, for methods that fall back after a swallowed exception:

```csharp
public static DateOnly ParseOrToday(string value)
{
    try
    {
        return DateOnly.Parse(value, CultureInfo.InvariantCulture);
    }
    catch (FormatException)
    {
    }

    return DateOnly.FromDateTime(DateTime.UtcNow);
}
```

## Known limitations

- Top-level statements, such as `Program.cs` without a `Main` method, are not checked. A try around host startup has no enclosing method to extract into.
- Only one trailing `return` is allowed. A method that needs any other statement before or after the `try` is reported, even when that statement is trivial.
- There is no code fix. Extracting a method needs a name and a signature that only a human can choose well.
